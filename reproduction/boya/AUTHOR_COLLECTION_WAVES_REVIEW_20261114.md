2026-11-14，审查 `author_collection_waves.py`、`author_collection_wave_resources.py` 与独立 wave exporter。最终源码与测试前后 SHA 不变，23 项组合测试通过；未发现阻止冻结新开发协议的代码问题。**这次审查没有启动 Kit、CGR、IK、规划、物理采集或训练，也没有实测并发吞吐。**

父进程继续持有原 GPU0 flock，子进程仅绕过同一把重复 GPU 锁，保留各自原 DRIVER 锁。每个真实 stage 继承父租约及本阶段槽位 FD，释放前检查整个进程组。独立运行两个准备线程与两个真实 Python 子进程，读取各子进程 `/proc/self/fd`，确认只继承本槽位和父租约，不继承兄弟线程的槽位。原采集 seed、场景布局、每场景四型顺序与原批处理源码固定版本均保留。

审查期间发现并已修复：未加锁同 inode FD 可被误认作租约；无槽位 build 的存活进程组不触发隔离；达到配额后仍派发整个剩余队列；每次派发重复核验所有子协议的大模型而产生平方级读取；配额跳过行缺三体身份；以及不同新运行目录之间可能绕过旧 native 准备孙进程的未释放记录。最终测试覆盖两处启动故障窗口、未知与存活进程不重启、父账本只写 g1 后恢复、子进程仅部分原始账本存在、配额原序接纳、超额成本保留及导出拒绝超额或未审计标签。

并发上限为 3 个 scene worker、3 个 Kit（capture 计入）、1 个 capture/CGR 观测阶段、3 个准备阶段和 2 个审计阶段。执行仍使用原 `sim.step(render=False)`，允许与观测重叠；本审查只核源码与纯操作系统约束，没有运行原生并发来验证内存峰值或实际速度。配额在完整 wave 结束后按原 scene index、g1/g6/g7/g8 顺序入账，后续已满 split 不再启动；在途超额保留原始标签和真实成本，父标签为 null，不能进入训练数组。缺失、基础设施失败与未知成本均不自动变成负样本。
