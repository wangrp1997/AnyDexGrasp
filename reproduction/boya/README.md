## 与作者流程的对应

固定上游 `c9c4a43`，原论文 arXiv 2502.16420v1 的 Algorithm 1：观测 → CGR → 采样手型并通过几何标定映射 → 碰撞检查 → 实际执行 → 成败标签。表示冻结，后续按原监督方法训练各手型的小评分头。作者用真实 UR5 及真实手采数；本适配用 Isaac Sim/PhysX 的完整 UR16e+Boya。抬升任务标签不等同作者搬运到箱子的实机成功定义。

原 `collect_dh3_grasp_data.py` 支持固定 `--grasp_type` 逐手型采集；原 `utils/collision_detector.py:134` 将开口乘 1.7，再经该手的标定表范围限制。这里显式记录原宽、扩展倍率、请求宽、是否限幅和实际参考宽。首轮固定手型1、附加深入0，只做一次已准入执行，尚非完整的多手型/多深入训练集。

## 组件与运行顺序

- `asset_adapter.py`：16手指电机、2腕、4条原随动关系；9个有对侧参考的现有手型。手型4缺拇指对侧标注，显式不构造。开度表基于源模型五个 distal pad，全部21个手部碰撞link保留。924槽是有限几何标定，不是924个成功经验。
- `prepare_adapter.py`：纯几何表、原手与完整24坐标机器人相对FK核对。最初v1用了旧中节接触标注，仅作接口诊断；正式v2使用源distal pad，两个版本输出保留。
- `render_isaac_observation.py`：Isaac 原生 RTX 相机生成 RGB-D/内参/外参，当前为孤立50mm方块与地面；机械臂未渲染到观测中。没有把物体姿态/分割/网格喂给表示网络。
- `../runtime/run_official_rgbd_frame.py`：既有官方冻结网络入口。选择原 `parse_preds` 的DH3版本仅解码共同表示，不运行其手评分器或 rig 方向/45–99mm候选门。输出为2048原始CGR候选。其历史固定 `example_boundary` 字符串不适用于新输入，另存勘误，不改冻结前向产物。
- `build_trial_pool.py`：固定声明手型，按CGR分数顺序检查；两侧翻转均显式记录；原开口扩展、手表限幅、全手源凸包/可见点云、21个接近采样及桌面检查。局部点云不能证明完整场景无碰撞，随后仍须完整臂原门。已知物体网格仅用于原机械臂路径/原生物理后端，不用于优化抓姿。
- `native_arm.py`：只读导入既有 `run_template_arm_positive.py`，新候选仍做新IK、新接近与抬升路径、原限位和原生碰撞审计。资产及所有输出显式指定；分块缓存重定到 AnyDex `outputs/`，Python使用 `-B`。原CanonDex实验与源码不改。
- `run_first_trial.py`：至多4个臂计划，首个准入者执行一次。旧成功计划只提供机器人配置和初态，不复用其抓姿/轨迹/标签。加候选绑定元数据前后，原控制数组逐数组精确相同。
- `trial_record.py`：源NPZ SHA＋原候选行号＋原2261特征＋作者规范化CGR480＋手型/开度/深入/翻转＋实际命令SHA＋执行回执。只有完整实际抬升试验能输出0/1；零步、基础设施问题、中止或无完整抬升阶段记null。

`backend.example.json` 为本服务器已有配置的显式示例，引用的资产不复制/不提交。大模型、观测、标定大表、轨迹和视频留 `outputs/` 或 `/mnt/public/datasets/`。原算法源码与原DH3结果不变。
