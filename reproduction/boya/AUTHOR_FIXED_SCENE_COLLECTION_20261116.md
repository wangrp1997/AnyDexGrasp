# 固定物理世界的连续采集

本轮按用户明确要求，将“反复冷建场景”改成类似实机的连续采集组织：机器人、地面、相机和物体资产一次创建，依次拍照、预测、准备、抓取；只在轮次边界摆放物体和复位机器人。不是只复用 Kit 进程再清场。

## 实现

`author_fixed_scene_collection.py` 是不依赖调试历史的有限批次入口；`author_live_collection.py` 负责父进程调度和常驻 CGR；`author_live_collection_service_v4.py` 单独拥有 Kit 主线程；`author_live_world.py` 及三个小修复层拥有同一个 native world。原采集、动作、碰撞、规划、物理和判断源码、CanonDex 均未改写。

初始化物体银行一次，当前固定两轮包含6个不同物体，每轮激活3件，其他物体放在工作区外的 `[10+i,10,5]`、清除旧外力，不在桌下穿地停车。它们仍属于仿真世界，成本必须同时报告 active 三体步与整个物体银行的时钟机会数，不能把银行体当作从物理世界删除。

每轮边界才允许写机器人和物体位置/速度。随后保留原750tick稳定初始化、逐点接触、原生20µm几何导入门和真实RTX RGB-D。capture 与 execute 之间没有 `SimulationContext.clear_instance/create_new_stage`、全局reset、物体位姿写入或速度清零；关节/物体状态、时钟、native句柄在执行前核对，首个执行tick从拍照时钟继续。

原机械臂准备以预张开手作为初值；常驻场景拍照时手处于统一张开状态。因此新绑定只将指令文件中的**初始手/腕坐标**换成实测值，原六臂初值和所有逐步目标、掌姿、phase、时间数组逐字节保持。原50tick settle继续发送预张开目标；之后原接近、250close、50hold、lift保持。没有用状态写入把活场景强行配到冷初值，也未新增触觉停止控制。

目标掌姿继续用此前的新g1预闭合宽度参考，原CGR/top500/source flip/extra-depth/全原碰撞/首选一次保留。原模型只加载一次，逐轮读新RGB-D；没有加载Boya评分头、训练、改模型或用CAD反选候选。原生几何资产在单个Kit内保留，当前仍逐轮做完整几何/物理审核。已完成执行的数值审核可在后台与下一轮初始化/准备重叠；完整接触日志仍按原已验证的隔离压缩与读回校验保存，没有宣称它已完全异步。

## 有限实跑与保留的接入失败

物理输入固定为原手动队列index3/4（fit00003/00004，seed2026111601）。这是已知场景的结构/耗时诊断，所有本轮结果exclude_training，不自动混入旧映射31条或此前新映射2条，也不启动正式全量/训练。每个独立版本最多1Kit、两轮各750初始化及各不超过8000抓取步；不因成败换候选或重抓。

public根前缀为 `/mnt/public/datasets/AnyDexGrasp/boya_collection_20261114_v1/live_world_control_20261116_v*`。每个版本的协议、精确源码归档和失败均保留：

## 适用范围

仿真计算CGR和路径时暂停积分，以保持观测—执行绑定；物理状态和求解器没有重建。实机不会随计算暂停，真实驱动仍需接入时延、状态复核、复位动作和真实标签来源。本轮是与实机相同的流程组织，不是已经完成Boya硬件标定或实机接口。

暂不以常驻结构本身宣称加速。完整新耗时需要以最后审核结束为止的parent wall记录；前期失败各另计。旧两场cold的26分54秒含中断恢复，工作stage合22分40秒，两者不是同一口径。新流程还改变了冷重建/速度清零/初始手状态和模型常驻随机序列，不能声称物理轨迹等价或用两个已知场景推长期产率。

第一轮执行审核与第二轮初始化重叠，表中各项不能简单相加充当总wall；启动、源绑定和调度间隔等由父进程2171.808秒覆盖。

**固定场景结构已验证，整体加速没有得到证明，本次完整流程仍然很慢。** 两轮初始化审核合569.534秒，抓取worker合796.834秒。原native循环测量中，`sim.step + asset update`合614.993秒，接触读取合13.709秒；这只能说明该时间桶占主导，不能直接归因GPU kernel、CPU碰撞或驱动。第一轮历史cold的native setup44.298秒，本次26.728秒；但循环从190.140秒变为249.236秒，不能只报setup缩短而宣称采集提速。

新旧第二轮候选分别raw296和raw1929，步数3558和2681；两次RGB-D也来自不同连续状态。因此不是相同指令/相同轨迹的配对比较，也不以两个场景的1正1负推长期产率或采满ETA。0物理的前5帧接触读取profile只提示源OBJ读取存在开销，不能证明它是完整审核变慢的主要原因；本轮没有据此修改几何、物理或审核门。后续提速应先分解实际物理等待与审核开销，固定场景本身已不需要继续重写。

## 运行入口与交付

通用入口`author_fixed_scene_collection.py`使用当前修复层，不要求先有三次失败。下例只演示如何冻结一个新的有限批次；`freeze`不启动物理，`run`才启动。新的根必须不存在；这是两场诊断配置，不是正式全量配额。

```bash
PYTHONPATH=reproduction/boya /home/wangrenpeng/tendon-spin/.venv/bin/python -B \
  reproduction/boya/author_fixed_scene_collection.py freeze \
  --source-batch /mnt/public/datasets/AnyDexGrasp/boya_collection_20261114_v1/manual_start_20261116_v2/batch \
  --geometry-template /mnt/public/datasets/AnyDexGrasp/boya_collection_20261114_v1/contact_pilot_20261116_v1/scenes/00/g1_contact/pipeline/READY.json \
  --root /mnt/public/datasets/AnyDexGrasp/boya_collection_20261114_v1/fixed_scene_user_v1 \
  --queue-indices 3 4

PYTHONPATH=reproduction/boya /home/wangrenpeng/tendon-spin/.venv/bin/python -B \
  reproduction/boya/author_fixed_scene_collection.py run \
  --root /mnt/public/datasets/AnyDexGrasp/boya_collection_20261114_v1/fixed_scene_user_v1
```

geometry-template只提供已核验机器人模型和物理建场配置，不执行其历史候选/命令；每轮重新拍照和CGR。入口支持预冻结1–8个ready场景、提前载入其物体银行、固定g1首选一次，硬性排除训练；正式扩采协议和真实硬件驱动尚未交付，不自动启动。

结果、协议、原完整接触与轨迹保存在public的v1–v4根；轻量副本和来源SHA见`evidence/author_fixed_scene_collection_20261116_v1/EVIDENCE.json`及`SUMMARY.json`。18项CPU检查通过（13新活场景+5既有映射，2.263秒），通用入口另通过0Kit静态冻结。四版源/input/archive绑定均保持，所有已登记进程组退出、预约released、锁可取、全局registry released；`HOST_FINAL_AUDIT.json`通过，无本轮后台采集/训练。
