## 固定参考

上游仍是 `c9c4a43df33e40860417c7e2dd02f5122d3b2da2`，原源码不改。部署以DH3公开分支为参考；Boya的模型、几何标定、驱动及仿真属于需要验收的替换。

| 项目 | 采用的公开设置 |
|---|---|
| 决策网络 | canonical480输入、20输出；显式 `num_two_finger_angle=1` 对应发布权重，公开训练默认240输出的差异保留 |
| 训练 | 100轮、batch128、Adam、lr/weight decay均5e-4、PolyLR power .99，每轮调度一次 |
| 损失 | 原最终ReLU后的选中输出MSE；preactivation不作为原算法主线 |
| 模型选择 | 原 `save_model` 在内部验证集的.5/.7/.9 P/R规则；不以外部实抓结果挑epoch或阈值 |
| 采集 | 单帧CGR、top500、固定所请求手型、每候选独立均匀随机0/10/20/30mm附加深入，不先用学习头挑采集样本 |
| 采集碰撞 | 3mm手表面体素、4cm原递归扫掠、允许进入体素的场景点数≤2、min width .01m、不开中心调整 |
| 部署 | 原identity＋10增强，CGR top1000→组合top3500→严格>.85→top400后碰撞；3mm、5cm原扫掠、允许点数0、min width .045m |

公开DH3采集与部署的翻面函数**本身不同**：采集在 `R[1,1]>0` 时反转第0、1列，部署反转第1、2列。这一差异未偷偷改成同一规则；Boya接近方向及两端动作语义还需验收。原DH3模型I/O加载器在循环内重置字典的问题，沿用[已公开说明的四头确定性加载](../runtime/README.md#original-dh3-single-frame-learned-hand-prediction)，不声称重现了有缺陷的目录遍历行为。完整作者训练历史仍不可由发布文件恢复。

## 本阶段实际完成

- `author_protocol.py` 从SHA固定的原文件提取数值代码，不导入真实机器人接口。采集top500/特征配对/单翻面/随机深入，以及递归扫掠体素内核已核验。
- `author_hand_clouds.py` 将Boya**全部21个手碰撞link**的原三角面按FK拼接，不转凸包，包含不参与手型的手指。四型g1/6/7/8各33状态，共132状态，每状态原方法均匀表面采样300000点，再生成1–5mm五种分辨率，合计3960万次表面采样、660份点云。它们是手几何资产，**不是3960万条训练数据**。
- `author_collision.py` 已用新全手表面点云接通**整个原碰撞类**：1.7倍开度、严格宽度门、LUT重映射、沿接近轴加深入、原递归扫掠及体素准入均实际执行原函数。Boya部分仍显式使用现有ff参考、手型范围裁剪和最近2mm计算标定表；不据此宣称接触参考或硬件标定已经通过。
- `author_training.py` 直接执行原 `train_one_epoch`、`eval_one_epoch`、`save_model`，保留原单样本尾批跳过、BN、最终ReLU/MSE以及按batch加权的原验证指标。保存改为安全state_dict，仅保留各阈值最近一次入选状态及全部选择事件，不保存每次改善的整个Python对象；入选状态用原发布推理类strict重载并逐值核验。原规则没有选出checkpoint时，不拿最后一轮偷偷替代。
- 扩采支持每型first100基线及显式first300/1000扩展，按同一采集顺序嵌套前缀、先选择再shuffle。合成集实际训练核验100条→1次更新、300条→3次更新，避免“采多了却仍被旧loader截成100条”。这些新组件均为opt-in，没有替换历史入口或自动晋级默认。

## 核验与成本

4项原组件测试及18个子测试通过；4项集成测试及7个子测试通过，覆盖原完整碰撞类、表面云载入、深入仅加一次、原选模型边界、发布推理strict重载、扩采有效进入训练、对象泄漏/外部行/重复试次拒绝。集成测试4.095s，原组件最终检查3.696s，不把两者当完整研发耗时。

独立 `audit_author_stage.py` 不导入CanonDex代码，以XML/NumPy URDF FK及源STL检查全部132状态、2772个link变换、660点云的有限值/边界/字节绑定和363槽绑定；最大FK矩阵误差2.220446049250313e-16。它没有检查受力或真实抓取可行性，也没有把有限值/边界检查冒称所有采样点到源面的逐点距离审计。

表面资产生成39.124s，NPZ约628MiB，只保存在忽略的 `outputs/boya_full_alignment_20261114_v2/hand_clouds/`。本阶段0新RGBD、0CGR前向、0正式数据优化更新、0正式新模型、0物理步；原435条、原8权重及历史结果不改。开发测试含8次合成Adam更新（含首次失败测试）；6个临时合成checkpoint经安全加载后随临时测试目录删除。

开发首轮出现NumPy特征被原代码调用`.cpu()`、缺少原epoch的scheduler绑定和Open3D本地libusb环境问题，修复后保留最终测试日志；这些是组件开发失败，不能说所有开发尝试首次就成功。v1来源审计和旧日志不覆盖；确认参考选择后的审计另存v2。新正式表面资产生成和独立资产审计均一次完成。无后台训练、物理或媒体任务。

## 距离正式扩采还缺什么

来源审计列出11项流程差异。新数值组件补齐不等于整个流程已对齐，当前 `pipeline_ready=false`。

1. 验收Boya pad、各型参考/接近方向与闭合动作语义，并在新采集路径接好原采集策略；旧评分前手/桌面过滤也不能继续冒称原DH3顺序。
2. 接通随机多物体的真实动态场景与搬运/投放动作，按新任务生成标签；旧单物体垂直提起标签不能直接改名为搬运成功。源物体粗凸代理和驱动假设仍须列明。
3. 在采集前固定对象划分、尝试预算、空计划处理、稳定初态与RGBD绑定、每型采数及内部验证策略。100/300/1000是已实现的容量及扩展规格，尚不是冻结并启动的400/1200/4000条采集队列。不按正例数停止，不把null补成负例。
4. 对新兼容任务的数据重新训练，完成内部检查并冻结模型；之后才做新的外部测试。旧435不自动混入，已有EGAD诊断对象也不再当最终未用测试集。

上述扩采、重训与实现工作已在本次用户授权范围内；旧阶段“停止扩样”是历史实验的停止线，不是重新索要许可的理由。当前阶段提交的是可核验组件与差异证据，完整论文复现仍未验收。
