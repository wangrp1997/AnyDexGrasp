# GPU 物理接通与吞吐诊断

GPU 物理、单／双环境共享时钟和逐点接触读取已实际接通；当前小规模配置仍慢，完整提起动作尚未验收。主要耗时实测在 `fetch_results`，不能把静态发现的多次主机读取当作主要原因。大规模采集、正式训练均未启动。GPU 诊断不增加有效训练标签，累计新标签仍为 14 fit＋1 internal；旧 435 条及八个权重不变。

## 实际接通范围

独立 GPU 入口复用既有 PhysX 场景、原控制 generator、共享时钟，以及 Isaac Lab 官方环境克隆接口。保留原三体几何、250 Hz、质量／摩擦／永久重力等效力、完整控制命令、逐点接触日志和原判定逻辑；没有改为平均接触或降低几何／控制精度。CPU→GPU 是显式后端变化，不假定接触轨迹数值等价。

实际 GPU0 用 UUID 固定；它在 NVML 中为 GPU0，但设备 minor 为 1，不能据 `/dev/nvidia1` 误认为使用了其它任务所在的 GPU1。初态和第一物理步两次只读检查均显示 `enableGPUDynamics=true`、GPU broadphase、simulation tensor view device ordinal 0、完整 filtered6 接触张量位于 CUDA。原生 1135 个凸体导入门通过，最大源面向外误差 17.654 µm。以上证明接通范围，不证明全部接触生成均由 GPU 完成或完整提起验收。

## 保留的失败与部分执行

- v1 在原手资源绑定前提前导入 physics，捕获不存在的旧默认 scene.xml：1 次 Kit、0 物理步。失败原件保留。v2 只提前调用既有 `bind_hand`；资源和驱动参数逐值不变，11 项 CPU 测试通过。
- v2 原冻结上限为单路 3024 tick、再双路 3374 tick；每组 1800 s、0 重试。实际仅启动单路，持续速度远慢于旧 CPU 执行，按此速度会超过原时限。
- 为避免超时 SIGTERM 跳过 Python 收尾，另存取消意图后仅向自有子进程组发送 SIGINT。确认 937 次 `sim.step` 返回、937 步观测；中断堆栈在下一次 `fetch_results`，第 938 步是否完成无法只读确认。因此积分成本为 **937 已确认＋最多 1 在途步**，不把计数器当精确的全部积分数。
- v2 执行到收尾 718.326 s，父流程 719.738 s；journal 正常关闭，标签及 raw label 均为空，排除训练。父流程停止，没有派发原第二组。没有完整末态，不能报正例、负例或完整门通过。

原运行目录：`/mnt/public/datasets/AnyDexGrasp/boya_collection_20261114_v1/gpu_vector_control_20261115_v{1,2}`。协议、失败日志、取消意图、部分轨迹和冻结源归档均保留，未覆盖或重启原目录。

## 吞吐结论与后续边界

现成批量实现已提供命令预载、跨环境资产 view 和合并状态读回；当前入口仍逐 lane 运行原完整读取循环。该路径可参考，但本次实测表明只改读取无法解决主要耗时。后续性能工作应先解释物理等待成本及更大批次的真实收益，再决定是否值得改批量数据通路；本轮没有追加大批次、降低精度、改求解器或生成训练标签。来源对照见[数据通路只读报告](AUTHOR_GPU_DATA_PATH_REVIEW_20261115.md)。

本阶段不能替换上一阶段的完整采集 ETA：fit 各型 1000 条仍只有约 15.02 天的条件情景，internal 三型原小样本零产出，4000＋800 总时间仍未知。执行段、初始化、准备、首次审计及 null 产率必须分开计算，不按 GPU／worker 数推算小时级完成。
